# NTec Инспектор — AR-помощник инженера

Мобильный помощник обходчика/инженера по предварительному осмотру промышленного
оборудования. Телефон наводится на планшет с фотографией агрегата, сервер
привязывает зоны узлов **без маркеров**, объединяет видеоаналитику с
телеметрией, объясняет диагноз и сохраняет осмотр в цифровую карточку.

Демо-стенд: два агрегата — **PUMP-001** (исправный) и **PUMP-002** (дефектный
участок), два разных QR-кода.

## Что работает

- **Идентификация**: QR → карточка оборудования: узлы, ресурс, состояние.
- **AR без маркеров**: привязка по признакам сцены (ORB/AKAZE + RANSAC) с
  fallback по контуру листа; полигоны 5 зон, EMA-сглаживание.
- **Видеоаналитика**: окно 60 с, статусы по каждому узлу, подтверждение
  признака по окну (≥30 % кадров, ≥3 кадров).
- **Движок правил**: 13 правил с evidence; 12/12 сценариев из дополнительных
  условий; четыре состояния вердикта, включая «недостаточно данных».
- **Визуальные каналы**: коррозия (YOLO11n, ONNX), текстурные аномалии
  (PatchCore v2), эвристики `cv_classic.defects`.
- **Локальная VLM**: qwen2.5vl:3b через Ollama — подтверждающий канал, не
  заменяет правила.
- **Мобильное приложение**: вкладки «Осмотр», «Дефекты», «Анализ»,
  «Оборудование»; светлая и тёмная темы; журнал событий; сохранение осмотра.
- **Офлайн**: все модели и сервер работают без интернета.

## Структура репозитория

```
backend/        FastAPI, PostgreSQL/SQLite, правила, симулятор телеметрии
mobile/         Flutter-приложение (Android)
ar_board/       генерация планшетов, QR, эталоны, маркерless-привязка
cv_classic/     манометр (OCR), эвристики дефектов, presence
anomaly/v2/     PatchCore-детектор текстурных аномалий + веса
corrosion/      YOLO11n-детектор коррозии, ONNX-веса, обучение
visual_align/   FeatureAligner для привязки по признакам сцены
docs/           архитектура, API, контракт, ограничения, runbook, дизайн
release/        готовый APK
tools/          demo_start.ps1 — поднять демо одной командой
```

## Быстрый старт

### 1. Backend

Нужен Python 3.10+. По умолчанию используется SQLite — PostgreSQL не обязателен.

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
# .env.example уже настроен на SQLite; для PostgreSQL раскомментируйте строку
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

При первом старте создаются таблицы и обезличенные демо-данные из
`backend/data/seed_rig.json`. Проверка: `http://127.0.0.1:8000/health`.

### 2. Локальная VLM (опционально)

```powershell
ollama pull qwen2.5vl:3b
ollama serve
```

Без Ollama работают правила, CV-каналы и вердикт; кнопка AI-проверки честно
вернёт ошибку канала.

### 3. Мобильное приложение

```powershell
cd mobile
flutter pub get
flutter build apk --release
```

Готовый APK уже лежит в `release/ntec-inspector.apk`. В настройках приложения
укажите `http://<IP-сервера>:8000`.

### 4. Демо-стенд

- Планшеты: `ar_board/out_real/board_A3.png` (PUMP-001) и
  `ar_board/out_defect/board_A3.png` (PUMP-002).
- Показ с экрана: `ar_board/screen/board_switch.html`, клавиши `1` / `2`.
- QR: `ar_board/qr/PUMP-001.png`, `ar_board/qr/PUMP-002.png`.
- Всё сразу: `powershell -ExecutionPolicy Bypass -File tools\demo_start.ps1`.

Сценарий: QR `PUMP-001` → чистый планшет → «норма»; QR `PUMP-002` →
дефектный планшет → коррозия/окисление, AI-проверка, сохранение осмотра.

## Модели и данные

Веса включены в репозиторий:

- `corrosion/models/corrosion_yolo11n_640.onnx` — базовый детектор коррозии;
- `corrosion/models/corrosion_board.onnx` — дообученный на кропах планшета;
- `anomaly/v2/models/*.npz` — PatchCore по пяти узлам;
- `visual_align/models/*.npz` — эталонные признаки для привязки.

VLM (`qwen2.5vl:3b`) — внешняя модель Ollama, в репозиторий не входит.
Телеметрия — симулятор (11 сценариев). Реальные данные заказчика в репозиторий
не входят: они хранятся в PostgreSQL на сервере. В `backend/data/seed_rig.json`
лежит обезличенный демонстрационный набор. Публичные датасеты и базовые веса
сохраняют свои лицензии; репозиторий — демонстрационный, не для коммерческого
использования.

## Ограничения

- Привязка без маркеров требует, чтобы планшет занимал заметную часть кадра
  (ориентир — ≥40 %).
- Детектор аномалий на нашем макете обучен на 6 кадрах нормы: AUROC 0.36;
  на MVTec AD — 0.968. Для 0.95+ нужно 30–50 кадров нормы.
- Коррозия на стенде размечена «по доске», не попиксельно.
- VLM — подтверждающий канал; на чужом домене осторожна (recall 0.33).
- Система не заменяет профессиональную диагностику и ТОиР.
