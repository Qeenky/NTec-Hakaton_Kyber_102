## 2. Отраслевые референсы: почему в промышленности такие цвета

Собраны 7 источников. Главный вывод, который они дают все вместе: **в промышленном интерфейсе цвет — это не декор, а код опасности.** Чем меньше цветов и чем строже правила, тем быстрее инженер находит проблему.

### Р1. KST ENERGO — собственный сайт (базовый референс)
- https://kst-energo.ru/ · логотип: https://kst-energo.ru/uploads/logo.svg
- Синий `#135AA6` + нейтрали, ноль декоративных акцентов, тонкие линии `#D5D9DE`.
- **Вывод:** бренд уже говорит «надёжность через сдержанность». Приложению не нужно ничего добавлять — нужно перестать спорить с брендом.

### Р2. ISA-101 / High Performance HMI (главный отраслевой стандарт)
- https://www.isa.org/getmedia/06130a38-f7af-4b35-8c9c-2c34f25c1977/The-High-Performance-HMI-Overview-v2-01.pdf
- Прямые цитаты: «Color, by itself, is never used as the sole differentiator of an important condition or status»; «Bright colors are primarily used to bring attention to abnormal situations, not normal ones».
- **Вывод:** норма — серая/нейтральная. Цвет появляется только там, где есть отклонение. Это ровно то правило, которого не хватает приложению: сейчас `#32D583` (зелёный) светится на каждом узле и «съедает» красный дефект.

### Р3. Rockwell Automation, Process HMI Style Guide
- https://literature.rockwellautomation.com/idc/groups/literature/documents/wp/proces-wp023_-en-p.pdf
- Таблица приоритетов: Urgent `#E22028`, High `#EC8629`, Medium `#F5E11B`, Low `#916AAD`; «State depiction cannot depend on color only… combined with other distinguishing characteristics such as shape».
- **Вывод:** нужен не только цвет, но и **форма/иконка** статуса. У нас 4 состояния — значит 4 разных силуэта бейджа, а не 4 кружка.

### Р4. ABB, High Performance HMI (Symphony Plus)
- https://new.abb.com/control-systems/symphony-plus/operations/high-performance-hmi
- Графика в оттенках серого, цвет — только для алармов, «consistent and careful use of color, shapes and motion».
- **Вывод:** серая шкала — не «скучно», а профессионально. 5–7 ступеней нейтрали достаточно для всей иерархии.

### Р5. Siemens Element — палитра промышленного дизайн-системы
- https://element.siemens.io/fundamentals/colors/color-palette/
- Фирменный «petrol» `#009999`, отдельные токены `focus #199FFF`, `red #e7001d`, `green #009a38`, `yellow #ffd200`; для каждого смысла — **два токена: заливка и текст** (доступный вариант).
- **Вывод:** бирюзово-синий — легитимный «инженерный» второй цвет (у нас он станет цветом живых данных/телеметрии). И: цвет заливки ≠ цвет текста, нужны отдельные пары токенов.

### Р6. Fluke — приборы для электриков и диагностов
- https://colorcodehub.com/brand/fluke.com (проверено по бренд-кейсу https://www.girvin.com/project/fluke/)
- `#FFC20E` (Supernova) + `#212121`; контраст жёлтый/чёрный **12.98:1**, жёлтый/белый — 1.62:1 (провал).
- **Вывод:** жёлтый работает как **предупреждение на тёмном**, а не как основной цвет. Янтарный `#FFB300` из текущего приложения — это «цвет Fluke», а не «цвет КСТ». Оставляем его только за состоянием «Внимание».

### Р7. Augury — мобильный предиктивный сервис (ближайший продуктовый аналог)
- https://www.augury.com/blog/augury-updates/not-all-mobile-apps-are-created-equal/ · https://apps.apple.com/us/app/augury-app/id6578444113
- В приложении ровно 4 статуса машины: **Acceptable / Monitor / Alarm / Danger**; карточка = «issue, severity, recommended remediation»; отдельно — «IoT Health» (состояние самих датчиков).
- **Вывод:** 4 состояния — отраслевая норма, совпадает с нашей моделью «норма / внимание / дефект / нет данных». И: состояние **датчика** надо показывать отдельно от состояния **узла** (у нас это смешано в строке «кадр 128 · привязка потеряна»).

### Р8. SKF — подшипники и диагностика вращающегося оборудования
- https://brandcenter.gallery/brands/skf (бренд-портал SKF Brand Hub)
- Палитра разложена на primary/secondary/tertiary, выгружается в ASE/LESS/SCSS — то есть бренд сам мыслит токенами. Точные HEX закрыты в бренд-портале, публично подтвердить не удалось (**не найдено**), но визуально система строится на глубоком синем + нейтралях.
- **Вывод:** даже производитель подшипников не использует «весёлые» цвета в коммуникации надёжности. Синий + серый — отраслевой консенсус.

### Свод: какие цвета ассоциируются с надёжностью и безопасностью

| Смысл | Цвет | Почему | Где нельзя |
|---|---|---|---|
| Надёжность, бренд, «всё под контролем» | **синий** `#135AA6` / `#4C9EEA` | цвет корпораций-интеграторов (КСТ, SKF, Siemens deep-blue), не конфликтует с алармами | не использовать для «нормы» — иначе норма = бренд = всё синее |
| Норма | **нейтраль + зелёный только точкой** | ISA-101: норма не должна привлекать внимание | нельзя заливать зелёным целые карточки |
| Внимание | **янтарный** `#FFC53D` | отраслевой стандарт (Fluke, Rockwell Medium) | нельзя для декора или «акцента» |
| Дефект / опасность | **красный** `#FF6B6B` | единственный цвет, который виден боковым зрением | нельзя для кнопок «удалить» и для статуса одновременно без формы |
| Нет данных | **серый** `#8B99A6` | честно показывает отсутствие сигнала, не путается с «нормой» | нельзя рисовать «норму» зелёным при отсутствии данных |
| Живые данные / телеметрия | **бирюзовый** `#35B8E0` | «холодный» цвет данных (Rockwell: live data — cool colors) | нельзя путать с бренд-синим в одном блоке |

## 3. Палитра

Все коэффициенты посчитаны по WCAG 2.1 (relative luminance). AA для текста — **≥ 4,5:1**, для крупного текста ≥ 3:1, для границ/иконок ≥ 3:1.

## 4. Типографика

**Только системные шрифты.** Внешние шрифты не подключаем: приложение работает на объекте без гарантированного интернета, а лишний вес APK и подмена метрик ломают вёрстку.

| Платформа | Шрифт | Реализация во Flutter |
|---|---|---|
| Android | **Roboto** (системный) | `fontFamily: null` |
| iOS | **SF Pro Text / Display** | `fontFamily: null` |
| Fallback | `system-ui`, `Segoe UI`, `Arial` | — |

Шрифт логотипа (узкий наклонный гротеск) **в UI не используется** — только в самом логотипе. Интерфейс — Roboto/SF, это осознанное упрощение.

### 4.1 Шкала

| Токен | Размер / интерлиньяж | Вес | Трекинг | Где |
|---|---|---|---|---|
| `display` | 40 / 44 | 800 | −1.0 | число-метрика героя (остаток ресурса, наработка) |
| `metric` | 28 / 32 | 800 | −0.5 | крупные числа в карточке |
| `h1` | 24 / 28 | 700 | −0.3 | заголовок экрана, имя оборудования |
| `h2` | 20 / 26 | 700 | −0.2 | заголовок секции |
| `title` | 17 / 24 | 600 | 0 | название узла, заголовок карточки |
| `body` | 16 / 22 | 400 | 0 | основной текст, рекомендация |
| `bodyStrong` | 16 / 22 | 600 | 0 | акцент внутри текста, значение |
| `label` | 14 / 18 | 600 | +0.1 | подпись метрики, кнопка второго уровня |
| `caption` | 12 / 16 | 500 | +0.2 | единицы измерения, служебные подписи |
| `overline` | 12 / 16 | 700 | +0.6 | НАДЗАГОЛОВОК КАПСОМ (максимум 1 на экран) |

**Минимум — 12 sp. Ниже 12 sp текста в приложении нет.** Сейчас в коде 24 места с 8–9.5 sp и 83 места с размером < 12 — это главная причина «мелких подписей».

Числа: обязательно `fontFeatures: [FontFeature.tabularFigures()]`, иначе значения «прыгают» при обновлении телеметрии.

### 4.2 Правила набора

- Максимум **две гарнитуры веса** в одном блоке (например 600 + 400). Три и более — визуальный шум.
- Заголовки — без точки в конце. Подписи — без двоеточий.
- Единицы измерения — `caption`, всегда через неразрывный пробел: `12,4 МПа`, `128 ч`.
- CAPS только для `overline`, не более одного на экран.
- Перенос строки в заголовке — максимум 2 строки, дальше `ellipsis`.
- Числа не сокращаем до «12,4к» — инженеру нужна точность; сокращаем только на графиках.

## 5. Сетка, отступы, радиусы, тени

### 5.1 Базовая единица — 4 px

Вся геометрия кратна 4. Шкала отступов:

| Токен | px | Применение |
|---|---|---|
| `space.1` | 4 | зазор иконка↔текст внутри строки |
| `space.2` | 8 | между элементами одной группы |
| `space.3` | 12 | внутри карточки между блоками |
| `space.4` | 16 | padding карточки, боковой отступ экрана |
| `space.6` | 24 | между карточками, между секциями |
| `space.8` | 32 | верх/низ экрана, крупные разделители |

Боковой отступ экрана — **16** на всех экранах. Никаких 14/18/22.

### 5.2 Радиусы

| Токен | px | Где |
|---|---|---|
| `radius.sm` | 8 | бейдж, чип, тег |
| `radius.md` | 12 | кнопка, поле ввода, строка списка |
| `radius.lg` | 16 | карточка, плашка диагностики |
| `radius.xl` | 24 | нижний шит, модальное окно |
| `radius.full` | 999 | «таблетка», круглый FAB |

### 5.3 Тени и elevation

Тёмная тема: **теней нет.** Глубина — только через цвет поверхности (`950 → 900 → 850`) и границу `#2E3A47`. Тень на чёрном фоне не видна и только «грязнит» экран в цеху.

Светлая тема: одна тень, только для шита и модальных окон:
`0 8px 24px rgba(20,24,28,0.12)`.

Градиенты запрещены (кроме затемнения под нижней панелью AR — это не декор, а обеспечение читаемости поверх камеры).

### 5.4 Размеры и зоны нажатия

| Токен | px | Комментарий |
|---|---|---|
| `touch.min` | 48 | абсолютный минимум (перчатки, ходьба) |
| `button.primary` | 56 | главная кнопка |
| `button.secondary` | 48 | второстепенная |
| `row.node` | 64 | строка узла |
| `ar.statusRow` | 28 | тонкая строка статуса AR (визуальная высота) |
| `ar.statusRow.hit` | 48 | зона нажатия вокруг неё (прозрачная) |
| `icon.sm` | 16 | внутри текста |
| `icon.md` | 20 | в кнопке |
| `icon.lg` | 24 | навигация |

Строка AR высотой 28 px **не является кнопкой** — у неё нет обязательной зоны 48 px по высоте; нажатие по ней расширяется невидимо до 48 px вниз. Это единственное исключение из правила 48, зафиксировано осознанно.

## 6. Обоснование решений (кратко)

1. **Тёмная тема — основная.** Цех, улица, ночная смена, перчатки. Тёмный фон на OLED меньше жжёт глаза и не «слепит» при взгляде от экрана на оборудование.
2. **Один акцент — бренд-синий.** Он же цвет действия. Не бывает «синей кнопки» и «синего статуса» одновременно: синий = «нажми».
3. **Норма — нейтральная, не зелёная.** Иначе зелёный перестаёт быть сигналом (ISA-101).
4. **Четыре состояния, четыре формы.** Цвет + силуэт + слово = читается при дальтонизме и на солнце.
5. **Минимум 12 sp.** Всё, что меньше, в перчатках и на ходу не читается.
6. **Один смысл — два токена (заливка/текст).** Прямое следствие того, что `#135AA6` не годится как текст на тёмном.
7. **Никаких декоративных градиентов и теней.** Простота важнее красоты.
