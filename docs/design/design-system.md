# Дизайн-система мобильного помощника инженера

Версия 1.0 · тёмная тема — основная · базовые токены: `tokens.json`
Палитра и обоснование: `brand.md` · аудит текущего UI: `ux-audit.md`

---

## 0. Принципы

1. **Один экран — одно действие.** Всё остальное убрано в детали или в шит.
2. **Статус → проблема → рекомендация → детали.** Никогда не наоборот.
3. **Цвет = смысл.** Синий — «нажми», красный — «дефект», янтарный — «проверь», серый — «нет данных».
4. **Цвет не единственный код.** Всегда цвет + форма + слово.
5. **Минимум 12 sp, минимум 48 px на нажатие.**
6. **Тёмный фон, без теней и градиентов.** Глубина — цветом поверхности.
7. **Центр AR-экрана неприкосновенен.** Ничего не перекрывает камеру в средней зоне.

## 1. Бейдж статуса

Четыре состояния. Форма различается, чтобы читалось без цвета.

```
 НОРМА (ok)              ВНИМАНИЕ (warn)
┌──────────────────┐    ┌──────────────────┐
│ (✓)  Норма       │    │ (!)  Внимание    │
└──────────────────┘    └──────────────────┘
 подложка #0E2A1D        подложка #3A2E0A
 текст    #3DD68C        текст    #FFC53D
 радиус 8 · h 28         радиус 8 · h 28

 ДЕФЕКТ (defect)         НЕТ ДАННЫХ (nodata)
┌──────────────────┐    ┌ ─ ─ ─ ─ ─ ─ ─ ─ ─┐
│ (✕)  Дефект      │    │ (?)  Нет данных  │
└──────────────────┘    └ ─ ─ ─ ─ ─ ─ ─ ─ ─┘
 подложка #3A1416        подложка #1E242B
 текст    #FF6B6B        текст    #8B99A6
 радиус 8 · h 28         пунктирная рамка
```

| Параметр | Значение |
|---|---|
| Высота | 28 px (`dense`) / 32 px (обычный) |
| Padding | 10 px по горизонтали, 4 px по вертикали |
| Иконка | 14 px, слева, зазор 6 px |
| Текст | `label` 14/18, вес 600 |
| Радиус | 8 |
| Рамка | 1 px, цвет состояния с alpha 0.55 |

**Правила:**
- Текст бейджа — всегда слово, не код (`ok`, `possible_defect` не показываем).
- Максимум 2 бейджа в строке. Третий — в детали.
- «Нет данных» **не** заменяется на «Норма» и наоборот. Пустой сигнал — это отдельное состояние.
- Бейдж не кликабелен. Если нужен переход — кликабельна вся строка.

## 2. Строка узла (node row)

Основная единица списка оборудования. Высота 64 px.

```
┌────────────────────────────────────────────────────────────┐
│ ▌  Подшипник приводного вала              (✓) Норма     ›  │
│ ▌  Ресурс: 4,2 года · с 12.03.2021                          │
└────────────────────────────────────────────────────────────┘
  ↑                                                          
  полоса статуса 4×40, радиус 2                                
```

```
 СХЕМА (64 px)
┌──┬─────────────────────────────────────────────┬─────────┬───┐
│▌ │ Название узла                    title 17/24│  БЕЙДЖ  │ › │
│▌ │ Ресурс: 4,2 года · с 12.03.2021  caption 12 │         │18 │
└──┴─────────────────────────────────────────────┴─────────┴───┘
 4  12                 flex                          8     16
```

| Параметр | Значение |
|---|---|
| Высота | 64 px (минимум), растёт при 2 строках названия |
| Padding | 16 слева, 12 справа, 12 по вертикали |
| Полоса статуса | 4 × 40 px, радиус 2, цвет состояния |
| Название | `title` 17/24, w600, max 2 строки |
| Ресурс | `caption` 12/16, `#8595A6`, max 1 строка, `…` |
| Шеврон | 18 px, `#55697E` |
| Фон | `#141B23`, разделитель снизу 1 px `#2E3A47` |

**Иерархия:** полоса + бейдж = «что с узлом», название = «что это», ресурс = «когда обслуживать». Больше ничего.

Запрещено: дата установки отдельной строкой, серийный номер, иконка типа узла, вторая метрика. Всё это — в карточке узла.

## 3. Карточка оборудования

Главный экран. Порядок строго: **статус → проблема → рекомендация → детали**.

```
┌──────────────────────────────────────────────────────────────┐
│  Насос центробежный ЦНС-38-220            ┌───────────────┐  │
│  Насосный цех №2 · инв. 4417              │ (✕)  Дефект   │  │
│                                           └───────────────┘  │
│                                                              │
│  ┌────────────────────────┐  ┌────────────────────────────┐  │
│  │ НАРАБОТКА              │  │ ОСТАТОК РЕСУРСА            │  │
│  │ 12 480 ч               │  │ 0,4 года                   │  │
│  └────────────────────────┘  └────────────────────────────┘  │
│                                                              │
│  ──────────────────────────────────────────────────────────  │
│                                                              │
│  Проблема                                                    │
│  Повышенная вибрация подшипника, 7,8 мм/с                    │
│                                                              │
│  Рекомендация                                                │
│  Заменить подшипник при ближайшей остановке                  │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │              Все детали и история                      │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

```
 ИЕРАРХИЯ (сверху вниз, по важности)
 ┌─────────────────────────────────────────┐
 │ 1. СТАТУС        бейдж, правый верх      │  ← видно с 2 метров
 │ 2. ИМЯ + объект  h1 24/28 + caption      │
 │ 3. 2 МЕТРИКИ     максимум две, 28/32     │  ← не больше двух!
 │ 4. ПРОБЛЕМА      1 строка, body 16       │
 │ 5. РЕКОМЕНДАЦИЯ  1–2 строки, bodyStrong  │
 │ 6. ОДНО ДЕЙСТВИЕ  кнопка/ссылка          │
 └─────────────────────────────────────────┘
```

| Параметр | Значение |
|---|---|
| Padding | 16 |
| Радиус | 16 |
| Фон / рамка | `#141B23` / 1 px `#2E3A47` |
| Имя | `h1` 24/28, w700, max 2 строки |
| Подзаголовок | `caption` 12/16, `#8595A6`, одна строка `…` |
| Метрики | 2 в ряд, зазор 12, значение `metric` 28/32 w800 tabular |
| Разделитель | 1 px `#2E3A47`, отступ 16/16 |
| «Проблема» | `overline` 12 caps `#8595A6` + `body` 16/22 |
| «Рекомендация» | `overline` + `bodyStrong` 16/22 `#F2F5F8` |
| Действие | одно, на всю ширину, высота 48 |

**Почему ровно две метрики.** Сейчас в `equipment_screen.dart` их четыре (наработка, нормативный срок, год выпуска, остаток ресурса) + «последнее ТО». Инженер на ходу считывает две. Остальное — в детали.

**Правило:** если статус «Норма» — блок «Проблема» не показывается вовсе (не пишем «Проблем не обнаружено»). Вместо него — дата следующего ТО одной строкой.

## 4. Плашка диагностики

Единица результата AI/правил. Три обязательных части: severity, evidence, рекомендация.

```
┌──────────────────────────────────────────────────────────────┐
│ ▌ ДЕФЕКТ · подшипник приводного вала                         │
│ ▌                                                            │
│ ▌ Повышенная вибрация 7,8 мм/с при пороге 4,5 мм/с           │
│ ▌ (12 замеров за 5 мин)                                       │
│ ▌                                                            │
│ ▌ → Заменить подшипник при остановке, проверить центровку     │
│ ▌                                                            │
│ ▌ Источник: вибродатчик VB-2 · 14:32          Подробнее ›    │
└──────────────────────────────────────────────────────────────┘
  ↑ полоса severity 4 px
```

```
 СХЕМА
┌─┬───────────────────────────────────────────────────────────┐
│▌│ СЕВЕРИТИ (overline 12 caps, цвет состояния) · узел        │
│▌│                                                           │
│▌│ Evidence: 1–2 строки, body 16, нейтральный текст          │
│▌│                                                           │
│▌│ → Рекомендация: 1–2 строки, bodyStrong 16                 │
│▌│                                                           │
│▌│ caption: источник · время                  ссылка 14      │
└─┴───────────────────────────────────────────────────────────┘
 4                         16 padding
```

| Параметр | Значение |
|---|---|
| Полоса severity | 4 px слева, на всю высоту, цвет состояния |
| Padding | 16 (слева 12, т.к. полоса) |
| Радиус | 16 |
| Фон | `#141B23`; для «Дефект» — `#1A1215` (едва заметный красный подтон) |
| Заголовок | `overline` 12/16 w700 + `title` 17/24 |
| Evidence | `body` 16/22, `#A9B8C7`, **максимум 2 строки** |
| Рекомендация | `bodyStrong` 16/22, `#F2F5F8`, со стрелкой `→`, max 2 строки |
| Мета | `caption` 12/16, `#8595A6` |
| Ссылка | `label` 14/18 w600, `#4C9EEA`, зона нажатия 48 |

**Правила:**
- Одна плашка = одна проблема. Три проблемы = три плашки, но на экране одновременно **не больше двух**; остальные — «Ещё 3».
- Evidence — факт с числом и порогом. Без числа это не evidence, а мнение.
- Рекомендация начинается с глагола: «Заменить», «Проверить», «Остановить».
- Если данных мало — severity = «Нет данных», evidence = чего не хватает, рекомендация = «Повторить съёмку». Не «норма».

## 5. Нижняя панель AR (сворачиваемая)

Главное правило: **в свёрнутом виде — не больше 96 px**, центр экрана свободен.

### 5.1 Свёрнутое состояние (по умолчанию)

```
┌──────────────────────────────────────────────────────────────┐
│                        ▁▁▁▁▁▁▁▁                              │  ← ручка 32×4
│  (✕) Дефект  ·  подшипник                    Ещё 2  ⌃        │  ← 1 строка
│  ┌────────────────────────────────────────────────────────┐  │
│  │                  Завершить осмотр                      │  │  ← 1 действие
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
   фон: градиент transparent → #0B0F14 (0.92)
   высота: 96 px + safe-area
```

```
 РАЗМЕТКА (свёрнуто)
┌───────────────────────────────────────────┐
│              ▁▁▁▁▁▁                       │  4
│  [бейдж]  [текст 1 строка]      [Ещё 2 ⌃] │  28
│  ┌─────────────────────────────────────┐  │  8
│  │        ГЛАВНОЕ ДЕЙСТВИЕ  (56)       │  │  56
│  └─────────────────────────────────────┘  │  12
└───────────────────────────────────────────┘
 итого 96 px
```

### 5.2 Развёрнутое состояние

```
┌──────────────────────────────────────────────────────────────┐
│                        ▁▁▁▁▁▁▁▁                        ⌄     │
│  (✕) Дефект · подшипник                                      │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ Повышенная вибрация 7,8 мм/с (порог 4,5)               │  │
│  │ → Заменить подшипник при остановке                     │  │
│  └────────────────────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ ( ! ) Внимание · сальник                               │  │
│  │ → Проверить подтёки                                    │  │
│  └────────────────────────────────────────────────────────┘  │
│  Ещё 1 проблема ›                                            │
│  ┌────────────────────────────────────────────────────────┐  │
│  │                  Завершить осмотр                      │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
   максимум: 45% высоты экрана, дальше — внутренний скролл
```

| Состояние | Высота | Что внутри |
|---|---|---|
| Свёрнуто | 96 px + safe-area | ручка, 1 строка статуса, 1 действие |
| Развёрнуто | ≤ 45% экрана | до 2 плашек диагностики + «Ещё N» + то же действие |
| Скрыто | 0 | остаётся только строка статуса 28 px |

**Правила:**
- Панель **никогда** не перекрывает верхние 2/3 экрана.
- Внутри всегда **одно** главное действие — «Завершить осмотр». Оно не меняется при разворачивании.
- Свайп вверх/вниз + тап по ручке. Двойной тап по центру камеры — свернуть.
- Все технические блоки (телеметрия, OCR, аналитика, чипы узлов) в панель **не попадают** — они в отдельном экране «Детали».

## 6. Строка статуса AR (28 px)

Единственный элемент в верхней зоне AR. Тонкая, не мешает камере.

```
┌──────────────────────────────────────────────────────────────┐
│ ‹   ● 12 к/с · узлы 3/7 · связь OK              ⧉ 4        │
└──────────────────────────────────────────────────────────────┘
    28 px, фон rgba(11,15,20,0.55), радиус 8
```

```
 ЗОНЫ (28 px)
┌────┬──┬───────────────────────────────────────┬───────┬─────┐
│ ‹  │● │ 12 к/с · узлы 3/7 · связь OK          │  ⧉ 4  │     │
│48  │8 │            caption 12/16               │ 48    │  8  │
└────┴──┴───────────────────────────────────────┴───────┴─────┘
  назад  точка   одна строка, ellipsis              журнал
```

| Параметр | Значение |
|---|---|
| Высота | 28 px (визуальная), зона нажатия расширена до 48 |
| Отступ сверху | 6 px от safe-area |
| Боковые отступы | 8 px |
| Фон | `rgba(11,15,20,0.55)`, радиус 8, без рамки |
| Точка связи | 8 px, цвет: `#3DD68C` live · `#35B8E0` connect · `#FFC53D` reconnect · `#FF6B6B` offline |
| Текст | `caption` 12/16 w600, **одна строка**, `…` |
| Иконка журнала | 20 px + счётчик, зона 48 |

**Что можно писать (словарь):**
- `12 к/с · узлы 3/7 · связь OK`
- `фото · привязка ослаблена`
- `кадр 128 · привязка потеряна`
- `нет связи · 4 с`

**Что нельзя:** `оверлеи по ответу /analyze`, `_fps`, `н/д`, `0x1F`. Технические имена — только в логах.

Строка статуса **не содержит** кнопок, кроме «назад» и «журнал». Всё остальное — в нижней панели.

## 7. Кнопки

### 7.1 Главная (primary)

```
┌──────────────────────────────────────────────────────────────┐
│                     Завершить осмотр                         │
└──────────────────────────────────────────────────────────────┘
  h 56 · радиус 12 · фон #135AA6 · текст #FFFFFF 16 w700
  контраст 6.91:1 ✅
```

### 7.2 Второстепенная (secondary)

```
┌──────────────────────────────────────────────────────────────┐
│                        Снять кадр                            │
└──────────────────────────────────────────────────────────────┘
  h 48 · радиус 12 · фон transparent · рамка 1.5 #55697E
  текст #F2F5F8 16 w600 · контраст рамки к фону 3.39:1 ✅
```

### 7.3 Опасная (danger)

```
┌──────────────────────────────────────────────────────────────┐
│                     Удалить осмотр                           │
└──────────────────────────────────────────────────────────────┘
  h 48 · радиус 12 · фон #C0323A · текст #FFFFFF 16 w600
  контраст 5.59:1 ✅
```

### 7.4 Состояния

```
 DEFAULT            PRESSED              DISABLED           LOADING
┌────────────┐    ┌────────────┐      ┌ ─ ─ ─ ─ ─ ┐      ┌────────────┐
│  Действие  │    │  Действие  │      │  Действие │      │  ◌  Отмена │
└────────────┘    └────────────┘      └ ─ ─ ─ ─ ─ ┘      └────────────┘
 100%              95% + overlay      40% прозрачность    спиннер + текст
```

| Состояние | Primary | Secondary | Danger |
|---|---|---|---|
| Default | `#135AA6` | прозрачный, рамка `#55697E` | `#C0323A` |
| Pressed | `#0F4A88` | фон `#1C2630` | `#A0262D` |
| Disabled | `#1C2630`, текст `#55697E` | рамка `#2E3A47`, текст `#55697E` | `#3A1416`, текст `#8595A6` |
| Loading | спиннер 16 + текст | то же | то же |
| Focus (TV/клавиатура) | рамка 2 px `#4C9EEA` + отступ 2 | то же | то же |

**Правила:**
- На экране одна primary-кнопка. Вторая primary — ошибка композиции.
- Опасная кнопка всегда требует подтверждения (шит снизу, кнопка подтверждения — danger).
- Текст кнопки — глагол в инфинитиве: «Завершить осмотр», «Снять кадр». Не «ОК», не «Далее».
- Иконка в кнопке — слева, 20 px, зазор 8. Не больше одной.
- Никаких кнопок высотой < 48. В AR допускается 44 только для иконок в строке статуса (зона 48).

## 8. Пустые состояния и ошибки

### 8.1 Пусто (нет данных / нет осмотров)

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│                          ╭─────╮                             │
│                          │  ▤  │   48 px, #55697E            │
│                          ╰─────╯                             │
│                                                              │
│                    Пока нет осмотров                         │
│            h2 20/26 w700, по центру                          │
│                                                              │
│         Отсканируйте QR на оборудовании,                     │
│         чтобы начать первый осмотр                           │
│         body 16/22, #A9B8C7, max 2 строки, по центру         │
│                                                              │
│              ┌────────────────────────┐                      │
│              │     Сканировать QR     │  ← primary 48        │
│              └────────────────────────┘                      │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 8.2 Ошибка (нет связи / сервер недоступен)

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│                          ╭─────╮                             │
│                          │  ⚠  │   #FFC53D                    │
│                          ╰─────╯                             │
│                                                              │
│                    Нет связи с сервером                      │
│                                                              │
│         Осмотр сохранён на телефоне и отправится              │
│         автоматически, когда связь появится                  │
│                                                              │
│              ┌────────────────────────┐                      │
│              │      Повторить         │  ← secondary 48      │
│              └────────────────────────┘                      │
│                     Работать офлайн                          │
│                     label 14, #4C9EEA                        │
└──────────────────────────────────────────────────────────────┘
```

### 8.3 Ошибка внутри блока (не блокирует экран)

```
┌──────────────────────────────────────────────────────────────┐
│ (!)  AI-проверка недоступна          Повторить               │
└──────────────────────────────────────────────────────────────┘
  h 48 · фон #3A2E0A · рамка 1 #FFC53D(0.6) · текст 14
```

| Тип | Иконка | Заголовок | Тело | Действия |
|---|---|---|---|---|
| Пусто | контурная 48 | `h2` 20/26 | max 2 строки | 1 primary |
| Ошибка сети | `⚠` `#FFC53D` | `h2` | max 2 строки + «данные не потеряны» | 1 secondary + 1 текстовая ссылка |
| Ошибка данных | `✕` `#FF6B6B` | `h2` | max 2 строки | 1 secondary «Повторить» |
| Нет прав | `⛔` `#8B99A6` | `h2` | 1 строка | нет |

**Правила:**
- В пустом состоянии всегда есть **одно** действие. Без исключений.
- Никогда не показываем стектрейс, HTTP-код, имя эндпоинта. Только «что случилось» и «что делать».
- Если данные уже собраны — обязательно пишем «данные сохранены». Это снимает тревогу.

## 11. Экранные правила (обязательные)

### 11.1 AR-экран: что где находится

```
┌──────────────────────────────────────────────────────────────┐
│  ЗОНА A — СТАТУС (28 px)                         не больше 1 │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ ‹   ● 12 к/с · узлы 3/7 · связь OK            ⧉ 4     │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  ЗОНА B — КАМЕРА + ОВЕРЛЕИ                    НЕПРИКОСНОВЕННА│
│                                                              │
│         ┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐                     │
│         │  (✕) подшипник  7,8 мм/с    │  ← оверлей узла     │
│         └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘                     │
│                                                              │
│              ▓▓▓ центр: только камера ▓▓▓                    │
│                                                              │
│  ЗОНА C — ЗАТВОР (64 px, по центру)                          │
│                        (  ◉  )                               │
│                                                              │
│  ЗОНА D — НИЖНЯЯ ПАНЕЛЬ (96 px свёрнуто / ≤45% развёрнуто)   │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  ▁▁▁▁  (✕) Дефект · подшипник              Ещё 2 ⌃    │  │
│  │  ┌──────────────────────────────────────────────────┐  │  │
│  │  │            Завершить осмотр                      │  │  │
│  │  └──────────────────────────────────────────────────┘  │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

| Зона | Что разрешено | Что запрещено |
|---|---|---|
| **A. Статус, 28 px** | точка связи, 1 строка текста, «назад», «журнал» | кнопки действий, логотип, меню, второй ряд |
| **B. Центр** | оверлеи узлов (контур + подпись), прицел | панели, списки, баннеры, реклама, туториал |
| **C. Затвор** | одна круглая кнопка 64 px | ряд из 3–4 кнопок |
| **D. Панель** | 1 строка статуса + 1 главное действие (свёрнуто) | телеметрия, OCR, аналитика, чипы (всё — в «Детали») |

**Правило центра:** средние **50% высоты** экрана не перекрываются ничем, кроме оверлеев и затвора. Если элемент не помещается — он уходит в панель или в «Детали», а не «сжимается».

**Правило безопасной зоны:** интерактив — не ближе 16 px к краям и не в верхних 44 px (шторка ОС).

### 11.2 Иерархия карточки

Строго сверху вниз, без перестановок:

```
1. СТАТУС        бейдж (цвет + форма + слово)
2. ЧТО ЭТО       имя + объект/локация
3. НАСКОЛЬКО     максимум 2 метрики
4. ПРОБЛЕМА      1 строка, с числом
5. РЕКОМЕНДАЦИЯ  1–2 строки, с глаголом
6. ДЕТАЛИ        одно действие
```

Если статус «Норма» — блоки 4 и 5 не показываются; вместо них одна строка «Следующее ТО: 12.03.2027».

### 11.3 Одно действие на экран

| Экран | Единственное главное действие | Второстепенные |
|---|---|---|
| Сканер QR | Сканировать | фонарик, ручной ввод (иконки) |
| Карточка оборудования | Начать осмотр | «Все детали» (ссылка) |
| AR-осмотр | Завершить осмотр | затвор (иконка) |
| Результат | Сохранить в журнал | «Повторить» (ссылка) |
| История | Открыть осмотр (тап по строке) | фильтр (иконка) |

Правило: **одна залитая кнопка на экран.** Вторая залитая кнопка — ошибка, а не «удобство».

### 11.4 Лимиты текста (N строк)

| Контекст | Максимум | Пример |
|---|---|---|
| Строка статуса AR | **1 строка**, ≤ 6 слов | `12 к/с · узлы 3/7 · связь OK` |
| Бейдж | **1 слово** + иконка | `Дефект` |
| Плашка диагностики: evidence | **2 строки** | `Вибрация 7,8 мм/с при пороге 4,5` |
| Плашка диагностики: рекомендация | **2 строки** | `Заменить подшипник при остановке` |
| Строка списка | **2 строки** (название + ресурс) | — |
| Карточка: любой блок | **3 строки** | — |
| Карточка целиком | **6 блоков** | — |
| Экран целиком (без скролла) | **60 слов** | — |
| AR-экран (свёрнуто) | **12 слов** | — |
| Пустое/ошибочное состояние | **2 строки** тела | — |

**Что делать с лишним:** обрезать `…` и убрать в «Детали». Не уменьшать шрифт. Не сжимать межстрочный. Не переносить в 4 строки.

### 11.5 Последовательность экранов

```
 QR-сканер ──▶ Карточка оборудования ──▶ AR-осмотр ──▶ Результат
    │                    │                    │              │
    └── ручной ввод      └── список узлов     └── «Детали»   └── журнал
                                              (телеметрия,
                                               OCR, аналитика)
```

Глубина — **не больше 3 уровней** от главного экрана. «Детали» — тупиковый экран, из него только «назад».

### 11.6 Тёмная и светлая тема

| | Тёмная (по умолчанию) | Светлая (опция) |
|---|---|---|
| Когда | цех, ночь, помещение | улица, солнце, бумажная работа |
| Фон | `#0B0F14` | `#F4F6F8` |
| Поверхность | `#141B23` | `#FFFFFF` |
| Тени | нет | одна, только для шита |
| Переключение | авто по датчику освещённости + ручной выбор в настройках | |

## 12. Чек-лист приёмки компонента

- [ ] Все размеры кратны 4
- [ ] Текст не меньше 12 sp
- [ ] Зона нажатия не меньше 48×48
- [ ] Статус читается без цвета (форма + слово)
- [ ] Контраст текста ≥ 4,5:1, графики ≥ 3:1
- [ ] Есть состояния: default / pressed / disabled / loading / focus
- [ ] Есть пустое состояние и состояние ошибки
- [ ] На экране не больше одной primary-кнопки
- [ ] Длинный текст обрезается `…`, а не ломает вёрстку
- [ ] Числа — tabular figures
- [ ] Нет теней и градиентов (кроме затемнения под AR-панелью)
