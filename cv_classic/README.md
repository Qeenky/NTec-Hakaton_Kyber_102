# cv_classic — чтение аналогового манометра классическим CV

Определяет показание стрелочного манометра по фотографии: **без обучения, без GPU,
без интернета, полностью офлайн и детерминированно**. Один вызов функции —
число, единица измерения, угол стрелки и `confidence`.

```
read_gauge(image) -> GaugeReading(value, unit, angle_deg, confidence, method, error)
```

Зачем это нужно в проекте: OCR-канал считывает аналоговый манометр с камеры, и если
его показание расходится с электронным датчиком давления больше чем на 15 % —
диагноз «дрейф калибровки / засорение импульсной линии». `cv_classic` — источник
этого показания.

Дополнительно (разделы 11–16) здесь есть **визуальные признаки дефектов узлов** —
коррозия, масляный подтёк, окисление клемм — и **маркерная проверка наличия
кожуха** (ArUco). Это тоже классическое CV: HSV-сегментация, моменты контуров,
Canny/градиенты, локальные статистики. Без обучения, офлайн, детерминированно,
с числовым `evidence` по каждому решению.

## 1. Что умеет и насколько хорошо

Синтетический датасет: 48 изображений (белый циферблат, чёрная шкала с делениями и
цифрами, красная/чёрная стрелка, случайные радиус 150–400 px, поворот прибора ±25°,
яркость, контраст, шум, размытие, блик). Диапазоны: 0–25/40/60/100 bar, 0–1.6 MPa,
0–300 psi; значения покрывают всю шкалу.

| прогон | успех | MAE, % диапазона | грубые промахи |
|---|---|---|---|
| основной набор, 48 кадров, конфиг на прибор | **100 % (48/48)** | **0.12 %** | **0 %** |
| отложенный набор, 40 кадров (другой seed) | **100 % (40/40)** | **0.12 %** | **0 %** |
| один канонический конфиг + компенсация поворота (`--auto-orient`) | 97.9 % (47/48) | 0.75 % | 2.1 % |

Цели задания: успех ≥ 85 %, MAE ≤ 3 %, промахи ≤ 10 % — выполняются с запасом.
Скорость на CPU: **~0.35 с/кадр** при полностью автоматическом поиске циферблата
(перебор HoughCircles) и **~0.09 с/кадр**, если в конфиге заданы `center`/`radius` —
это боевой режим после калибровки, когда камера и прибор зафиксированы.

«Успех» = ошибка ≤ 5 % диапазона шкалы; «грубый промах» = ошибка > 10 % диапазона
или отказ. MAE считается по всем кадрам, где отказ = 100 % диапазона (честная метрика,
а не только по удачным).

## 3. Схема углов

Углы во всём пакете (конфиг, `angle_deg`, калибровка) — в одной системе:

```
            90° (вверх)
                |
  180° ---------+--------- 0°   (вправо, 3 часа)
                |
          270° / -90°
положительное направление — против часовой стрелки
```

Типовой манометр: `angle_min = 225°` (низ-лево, «0»), `angle_max = -45°` (= 315°,
низ-право, конец шкалы), развёртка 270° **по часовой стрелке**. Значение растёт при
уменьшении угла, поэтому для `clockwise: true`:

```
frac   = ((angle_min - angle) mod 360) / ((angle_min - angle_max) mod 360)
value  = value_min + frac * (value_max - value_min)      # клип в [0, 1]
```

Для `clockwise: false` формула зеркальная. Углы нормализуются в [0, 360), переход
через 0° обрабатывается по модулю.

## 4. Калибровка под свой манометр

Нужна потому, что у приборов разные диапазоны и разное положение нуля.

```powershell
cv_classic\.venv\Scripts\python.exe -m cv_classic.calibrate `
    --image gauge.jpg --out cv_classic\configs\gauge_01.json `
    --value-min 0 --value-max 16 --unit MPa
```

Клики мышью по картинке: **1) центр циферблата → 2) точка начала шкалы («0») →
3) точка конца шкалы**. `R` — сброс, `S` — сохранить, `Q`/`ESC` — выход. Радиус
циферблата определяется автоматически (`HoughCircles`), можно задать `--radius`.

Безоконный режим (скрипты/CI) — те же три точки числом:

```powershell
... -m cv_classic.calibrate --image g.png --out c.json `
    --points "411.9,422.9 238.8,647.1 636.1,596.0" --value-min 0 --value-max 1.6 --unit MPa
```

Фактическое время калибровки (headless, включая поиск радиуса): **0.48 с**;
в GUI — это три клика, ~5–10 с на прибор.

Файл конфига (`cv_classic/configs/gauge_010.json`, реальный пример):

```json
{
  "angle_min": 232.329, "angle_max": 322.329,
  "value_min": 0.0, "value_max": 1.6, "unit": "MPa", "clockwise": true,
  "center": [411.9, 422.9], "radius": 354.29,
  "auto_orient": false, "target_size": 512,
  "min_needle_frac": 0.3, "min_confidence": 0.15,
  "image_path": "...gauge_010.png"
}
```

* `center`/`radius` — подсказка: если заданы, круг не ищется (быстрее и стабильнее).
* `auto_orient: true` — включить компенсацию поворота прибора по «пустому» сектору
  шкалы; тогда `angle_min/angle_max` задаются в системе самого прибора
  (225° / -45°), а не в системе изображения. По умолчанию выключено, потому что
  калибровка кликами уже даёт абсолютные углы для конкретной установки.

## 5. Как это работает (по шагам)

1. **Препроцессинг.** Grayscale, гауссово размытие, CLAHE; вес CLAHE растёт, если
   кадр «плоский» (`std < 45` — тогда 75 % CLAHE). Canny с порогами, адаптированными
   к медиане градиента (иначе на тёмных/малоконтрастных кадрах рёбер нет вообще).
2. **Поиск циферблата.** `cv2.HoughCircles` по сетке параметров
   (`dp ∈ {1.0, 1.5}`, `param1 ∈ {80, 130}`, `param2 ∈ {28, 42, 60}`) + кандидаты по
   самому большому светлому пятну и по круглому контуру (fallback). Каждый кандидат
   скорится по правдоподобию: поддержка окружности рёбрами **при реальном перепаде
   яркости**, относительный контраст лицо/корпус, однородность лица, тёмная ступица,
   наличие рисок в кольце. Затем центр уточняется подпиксельно: 180 лучей, поиск
   градиента «лицо → корпус», МНК-подгонка окружности с отбраковкой выбросов.
3. **Нормализация.** Круг вырезается, масштабируется так, чтобы радиус стал
   0.47·512 = 240 px (центр в центре кадра). При `auto_orient` поворот оценивается
   по «пустому» сектору шкалы: гистограмма тёмных пикселей в кольце 0.74–0.97 R,
   самый длинный провал ~90° → его центр указывает вниз (270°), разница даёт поворот.
   Точность на синтетике: 47/48 кадров в пределах ±2°.
4. **Поиск стрелки** (на нормализованном кадре):
   * маска «тёмное + красное» (HSV): ловит и чёрную, и красную стрелку;
   * **`HoughLinesP`** из центра: оставляем отрезки, у которых расстояние от центра
     до прямой < 0.10 R, берём самый длинный — он проходит через ось;
   * **альтернатива** — профиль длины непрерывного тёмного пробега по 720 углам
     (старт у центра, допускаются разрывы до 10 % радиуса — это спасает стрелку,
     разорванную бликом или размытием);
   * всё считается на **трёх порогах** (тугой / Otsu / мягкий), чтобы не терять
     светлую часть стрелки; если Hough и профиль согласны в пределах 6° — углы
     усредняются по длине, метод `hough+histogram`;
   * проверка «прямизны»: поперечный разброс тёмных пикселей у луча должен быть
     < 3 % радиуса, покрытие по радиусу ≥ 0.6 — иначе это не стрелка (так
     отбраковывается шум).
5. **Угол → значение** по линейной интерполяции конфига (см. §3), с клипом и
   отметкой `clamped` в debug.
6. **Confidence** = 0.35·качество круга + 0.25·длина стрелки + 0.15·стабильность
   угла на двух порогах + 0.10·согласие методов + 0.15·прямизна.

Коды ошибок (возвращаются в `error`, `value = None`, исключений наружу нет):
`bad_image` (меньше 40 px / не декодируется), `no_dial`, `no_needle`,
`needle_too_short` (< 30 % радиуса), `low_confidence`, `bad_config`,
`internal_error`.

## 6. Проверка: что именно было измерено

```powershell
> ...\python.exe cv_classic\scripts\eval_synthetic.py
изображений: 48   время: 19.0 c (396 мс/шт)
успех (ошибка <= 5% диапазона): 48/48 = 100.0%   цель >= 85%  -> OK

грубые промахи (>10% диапазона): 0/48 = 0.0%     цель <= 10%  -> OK
средняя confidence: 0.92
```

`eval_synthetic.py` печатает таблицу «файл | истина | распознано | ошибка %» и
сводку; код возврата 1, если цели не достигнуты. `truth.json` хранит для каждого
кадра истинное значение, угол стрелки и параметры шкалы (включая поворот прибора).

Тесты (`pytest`): 5 синтетических кадров (края и середина шкалы, повороты от −20°
до +20°, красная и чёрная стрелка, цветная зона), «пустое» изображение, шум, слишком
маленький кадр, обратимость угол↔значение, round-trip JSON-конфига и сквозной тест
«3 клика → конфиг → чтение».

## 7. Ограничения (измерено стресс-тестом, 20 кадров на условие)

```
условие         успех   MAE %   промахи   что это
clean            100%    0.15      0%     базовые кадры
tilt15           100%    0.25      0%     наклон 15°
tilt30            95%    3.72      5%     наклон 30° (эллипс вместо круга)
tilt45            90%    8.88     10%     наклон 45°
blur             100%    0.11      0%     размытие Гаусса 11×11
lowcontrast       95%    0.48      0%     контраст, сжатый в 3.6 раза
dark             100%    0.12      0%     яркость ×0.45
glare_mild        95%    2.18      5%     блик +110 на стрелке
glare             15%   75.93     85%     блик +235 (пересвет до белого) на стрелке
```

Что ломает алгоритм и почему:

* **Прямой блик/пересвет поверх стрелки** — информация физически потеряна (пиксели
  стрелки становятся белыми). Решение: переснять со смещением камеры/света или
  использовать несколько кадров. Частичный блик (не до 255) переживается: 95 %.
* **Глянцевое стекло** — то же самое плюс ложные дуги окружностей; спасает то, что
  блик обычно статичен и не проходит через центр.
* **Наклон > 30°** — циферблат становится эллипсом, ошибка угла растёт (90 % успеха
  при 45°). Нужна перспективная коррекция по 4 точкам (не реализована).
* **Стрелка сливается с фоном** (светлая стрелка на светлом лице, тёмное лицо с
  тёмной стрелкой) — маска «тёмное + красное» не сработает: `no_needle`. Нужен
  другой признак (цвет или движение) — вне области текущей реализации.
* **Нелинейная градуировка** (логарифмическая, сжатая на концах) — модель линейна по
  углу, на концах шкалы будет систематическая ошибка. Лечится добавлением опорных
  точек в конфиг (сейчас их две).
* **Стрелка короче 30 % радиуса / шкала без стрелки** — по заданию это ошибка
  `needle_too_short`, значение не выдаётся.
* **Нестандартная шкала** (не 270°, зеркальная, с нулём справа) — задаётся
  калибровкой (`clockwise: false`, любые `angle_min/angle_max`), но `auto_orient`
  рассчитан на «пустой сектор ~90° внизу».

## 8. Встраивание в backend

Одна функция, на вход PIL/np/путь, на выход — обычный dict (без numpy внутри):

```python
from cv_classic import read_gauge_dict, GaugeConfig
from PIL import Image

CFG = GaugeConfig.from_json("cv_classic/configs/gauge_01.json")

def gauge_value(image: Image.Image) -> dict:
    """image — то, что пришло из OCR-канала (PIL или np.ndarray)."""
    return read_gauge_dict(image, CFG)
```

Пример ответа:

```python
{"value": 0.334, "unit": "MPa", "angle_deg": 176.0, "confidence": 0.92,
 "method": "hough+histogram", "error": None, "debug": {...}}
```

Рекомендуемая логика диагностики: считать расхождение `abs(value - p_sensor) /
range > 0.15` только если `error is None and confidence >= 0.5`; иначе — «не удалось
прочитать манометр, требуется пересъёмка» (иначе будет ложный диагноз).

Пример для FastAPI:

```python
@app.post("/gauge")
async def gauge(file: UploadFile):
    img = Image.open(io.BytesIO(await file.read())).convert("RGB")
    return read_gauge_dict(img, CFG)
```

## 10. Что говорить жюри

* Это **классическое компьютерное зрение**: Hough-преобразование, пороги Otsu,
  полярная гистограмма, МНК-подгонка окружности. **Обучения нет** — датасета не
  требовалось, нет вероятностных весов, нет «чёрного ящика».
* **Работает офлайн и на CPU**: ~0.1 с на кадр в боевом режиме с калиброванным
  конфигом (~0.35 с при авто-поиске циферблата), ни GPU, ни интернета, ни весов
  модели. Запускается на ноутбуке инспектора и в контейнере без ML-стека.
* **Детерминированно**: один и тот же кадр → один и тот же ответ (никакой
  случайности, seed не нужен). Это важно для метрологии и для разбора инцидентов.
* **Объяснимо**: в `debug` видно найденный круг, длину стрелки, углы каждого метода,
  стабильность и из чего сложился `confidence`. Любой ответ можно нарисовать и
  показать: «вот циферблат, вот стрелка, вот угол 176°».
* **Калибруется за 3 клика** под любой прибор (0.5 с) — не нужно переобучение.
* **Честно про отказы**: 5 кодов ошибок вместо тихого вранья; на пересвеченной
  стрелке алгоритм прямо говорит «не прочитал», а не выдаёт случайное число —
  для диагностики это критично.
* Ограничения измерены стресс-тестом (таблица выше), а не заявлены «на глаз».

## 11. Визуальные признаки дефектов (`defects.py`)

Детекторы получают **вырезанную ROI узла**, а не весь кадр, и возвращают
`DefectScore(score, present, confidence, evidence, error)`:

```python
from cv_classic import detect_rust, detect_oil, detect_oxidation, detect_defects

d = detect_rust(roi_bgr)          # roi_bgr: np.ndarray BGR / PIL / путь
d.score        # 0..1, «сколько признаков коррозии»
d.present      # score >= threshold из configs/defects.json
d.confidence   # насколько оценка далека от порога и есть ли вообще маска
d.evidence     # {"mask_frac": 0.23, "grad_ratio": 2.2, "parts": {...}, ...}
d.error        # None | "bad_image" | "roi_too_small" | "bad_config"

all_defects = detect_defects(roi_bgr)  # {"rust": {...}, "oil": {...}, "oxidation": {...}}
```

### Что считает каждый детектор

| детектор | физический смысл | признаки (все — в `evidence`) | вес в score |
|---|---|---|---|
| `detect_rust` | коррозия металла | доля пикселей в HSV-коричнево-оранжевом диапазоне (H 3–26 OpenCV, S≥0.30, V 0.08–0.85, R−B≥18); плотность Canny внутри/снаружи; отношение среднего градиента внутри/снаружи (`grad_ratio`); отношение high-pass std (`hf_ratio`); неровность края (площадь выпуклой оболочки / площадь контура); прирост насыщенности | frac .22, edge .12, grad .20, hf .18, shape .14, chroma .14 |
| `detect_oil` | масляный подтёк / пятно | тёмная маска (V ниже медианы ROI на ≥10 % и ниже med−2·MAD); заливка пятна вместе с бликами; площадь; удлинение и вертикальность по моментам; `glint_frac` — доля компактных ярких бликов на кромке пятна; внутренний размах V (p95−p05); резкость кромки (градиент на границе / средний градиент ROI) | area .18, shape .22, glint .24, spread .20, boundary .16 |
| `detect_oxidation` | потемнение/окисление клемм | локальное потемнение относительно медианы ROI; потеря насыщенности (только если фон не серый, `min_sat_out`); `grain_ratio` — относительная энергия Лапласиана; площадь пятна; штраф, если тёмная маска упирается в границы ROI (общая тень); штраф за рыже-коричневый цвет (это коррозия, а не оксидная плёнка); штраф за резкую кромку (это масло/краска) | darkening .30, desat .20, grain .28, area .22 |

Пороги (`configs/defects.json`, все значения с комментариями):
`rust 0.50`, `oil 0.60`, `oxidation 0.52`.

Технические детали, которые оказались важны:

* ROI уменьшается до стороны ≤ 384 px (`common.max_side`) — статистики стабильнее,
  скорость выше; на ROI меньше 24 px возвращается `roi_too_small`.
* Плоская ROI (std яркости < 1.5) — не ошибка: `score=0`, `error=None`,
  `evidence.reason="flat_roi"`; дефект просто не виден.
* Масло: тёмную маску нельзя мерить «как есть» — яркие блики в неё не попадают,
  и блеск всегда получался бы нулевым. Пятно заливается по контуру
  (дилатация → заливка → эрозия), а блик ищется как компактная яркая компонента
  **рядом** с пятном, с ограничением по относительной площади. Соседняя
  освещённая поверхность у тени — большая компонента, она отбрасывается.
* Окисление: рыжие пиксели в тёмной области — голос за коррозию
  (`rust_like_frac`), поэтому ржавое пятно не дублируется как «окисление».
* Все пороги и веса — только в JSON. В функциях чисел-порогов нет
  (есть резервная копия `DEFAULT_CONFIG` в модуле на случай потери файла).

## 12. Маркерная проверка наличия (`presence.py`)

На защитном кожухе муфты наклеен ArUco-маркер: `DICT_4X4_50`, **id 4**.
Если маркер не найден в зоне кожуха — кожух отсутствует или смещён. Это
промышленный приём «проверка наличия по метке», а не подмена детекции объекта.

```python
from cv_classic import check_marker, check_marker_in_roi

r = check_marker(frame_bgr, 4)
r.present     # True/False
r.confidence  # 0..1
r.corners     # [[x, y], ...] 4 точки или None
r.error       # None | bad_image | bad_dictionary | marker_too_small | bad_roi
r.reason      # marker_found | marker_not_found | marker_too_small | outside_roi

# маркер должен быть именно в зоне кожуха (полигон в координатах кадра)
r = check_marker_in_roi(frame_bgr, 4, roi_polygon=[(x1, y1), (x2, y2), ...])
```

* `present=True`, только если сторона маркера ≥ 12 px; иначе
  `error="marker_too_small"` — лучше пропустить кадр, чем врать про кожух.
* В `check_marker_in_roi` дополнительно требуется, чтобы центр маркера был внутри
  полигона и ≥ 50 % его углов лежали в полигоне. Случайный маркер в другом месте
  кадра не даёт ложное «присутствует»: вернётся `present=False`,
  `reason="outside_roi"`, а координаты маркера останутся в `corners` для отладки.
* `confidence` для «маркера нет» зависит от текстурированности кадра: на пустой
  засветке она ниже (0.55), на нормальном кадре выше (0.70).

## 13. Синтетика и реальные метрики

```bash
# 140 ROI + truth.json -> cv_classic/data/defects/
python cv_classic/scripts/make_defect_samples.py

# train/test 50/50, порог выбирается только на train, метрики на test
python cv_classic/scripts/eval_defects.py
```

Состав датасета (все изображения синтетические, детерминированные по seed):
40 чистых негативов (градиенты, шум, царапины, мягкие и резкие тени, блики),
30 ржавчины (пятна 5–40 % площади), 30 масла (тёмные глянцевые blob'ы с хвостом
вниз), 20 окисления, 20 смешанных/пограничных (6 rust+oil, 4 мелкой ржавчины
2–4 %, 4 ровной рыжей краски, 3 сухих коричневых разводов, 3 «тень + блик»).

|---|---|---|---|---|---|---|

Цели precision ≥ 0.85, recall ≥ 0.80, FPR ≤ 10 % выполнены на holdout по всем
трём классам. Цифры получены командой выше и сохранены в
`data/eval_defects_holdout.json` (там же по-файловые scores и разбивка).

### Что реально ошибается (holdout)

* **1 FN у ржавчины** (`rust_068`, score 0.473): гладкое низкоконтрастное пятно
  на тёмном фоне — текстура почти как у краски, признаков «шершавости» нет.
* **2 FN у масла** — оба на смешанных ROI `rust_oil`: в одном случае масло
  перекрыто ржавчиной (score 0.17), в другом пятно слишком близко к порогу.
* **2 FP у масла** — на ржавых ROI (score 0.76 и 0.83): тёмное ржавое пятно с
  рыжими бликами похоже на глянцевый подтёк. На чистых негативах FP = 0.
* **2 FN у окисления** (score 0.512 и 0.513): слабое потемнение, почти на пороге.
* Ложных срабатываний на «рыжей краске», сухой грязи и «тени с бликом» при
  рабочих порогах на holdout нет (0/10), но при снижении порога они появляются
  первыми — это и есть цена эвристик.

### Самые информативные признаки

* **ржавчина**: `grad_ratio` (1.6–6.7 у ржавчины против 0.8–1.3 у ровной краски),
  `hf_ratio`, `chroma`, `frac`, `shape`. Без текстурных признаков одна лишь
  HSV-маска ловила бы рыжую краску.
* **масло**: `spread`/`v_p95` (внутренний размах яркости; AUC 0.97–0.98),
  `boundary_grad`/`boundary_ratio`, `glint_frac`. Цвет и площадь — вторичны.
* **окисление**: `grain_ratio` (AUC 1.00 на holdout), `darkening`, `desat`.
  Резкая кромка и рыжий цвет — главные стоп-факторы.

### Честно про методику

Синтетика и признаки разрабатывались итеративно: я смотрел на весь датасет,
поэтому разбиение train/test внутри `defects` оптимистично. Числа holdout
(датасет с другим seed, пороги уже зафиксированы) — более честная оценка. Это
всё равно **синтетика**: она проверяет, что признаки и пороги работают, но не
заменяет калибровку на реальной камере.

## 14. Как подключить к backend

Функции принимают только ROI и возвращают обычные dict (внутри нет numpy):

```python
from cv_classic import detect_defects, check_marker_in_roi, load_defect_config

DEF_CFG = load_defect_config()

def analyze_node(frame_bgr, zone, guard_polygon=None) -> dict:
    """zone = (x, y, w, h) в координатах кадра; guard_polygon — полигон кожуха."""
    x, y, w, h = [int(v) for v in zone]
    roi = frame_bgr[y:y + h, x:x + w]
    defects = detect_defects(roi, DEF_CFG)

    guard = None
    if guard_polygon is not None:
        # маркер id=4 наклеен на защитный кожух муфты
        guard = check_marker_in_roi(frame_bgr, 4, guard_polygon).as_dict()

    return {"defects": defects, "guard": guard}
```

Пример ответа (сокращённо):

```python
{"defects": {
   "rust": {"score": 0.78, "present": True, "confidence": 0.92,
            "error": None,
            "evidence": {"mask_frac": 0.23, "grad_ratio": 2.21,
                         "hf_ratio": 2.14, "hull_ratio": 1.45,
                         "parts": {"frac": 1.0, "grad": 0.72, "hf": 0.88,
                                   "shape": 1.0, "chroma": 1.0},
                         "threshold": 0.5}},
   "oil":  {"score": 0.12, "present": False, "confidence": 0.55, ...},
   "oxidation": {"score": 0.31, "present": False, "confidence": 0.70, ...}},
 "guard": {"present": True, "confidence": 0.86,
           "corners": [[210.4, 96.1], [305.2, 92.8], ...],
           "error": None, "reason": "marker_in_roi"}}
```

Как это ложится на правила диагностики (визуальный канал — **подтверждающий**,
не единственный источник):

| правило | сигнал из `cv_classic` | как использовать |
|---|---|---|
| `seal_leak` | `rust.present` + рост `rust.score` между осмотрами | усиливает вывод, если падает давление/растёт утечка; сам по себе — «осмотреть узел» |
| `mechanical_looseness` | прямого визуального детектора нет; косвенно `oil`/`rust` рядом с крепежом | не выдавать как диагноз, только «есть загрязнение/коррозия» |
| `lubrication_degradation` | `oil.present` и `oil.score` | «есть подтёк/замасливание» — повод проверить смазку |
| `electrical_contact` | `oxidation.present` (плюс отсутствие `rust.present`) | «клемма потемнела/окислилась» — проверить контакт |
| `guard_removed` | `guard.present == False` и `guard.confidence >= 0.55` | кожух отсутствует/смещён; при `error != None` — пересъёмка, а не диагноз |

Рекомендуемая логика: учитывать визуальный признак только если `error is None`
и `confidence >= 0.6`; при `error` — не менять диагноз, а запросить кадр
лучше. Порог `present` — из `configs/defects.json`; его можно менять без
переобучения (это и есть калибровка под объект).

## 15. Ограничения (честно)

* Это **эвристики, а не нейросеть**. Детекторы опираются на цвет, текстуру,
  форму и локальный контраст. Они не «понимают» объект: если пятно выглядит как
  ржавчина, оно будет названо ржавчиной.
* **Рыжая краска / коричневая грязь** — главный источник ложной коррозии.
  На синтетике помогает текстура (краска ровная), но на реальной поверхности
  с грязью и потёртостями FPR вырастет.
* **Масло против тени**: масло ищется по глянцу, вытянутости и резкой кромке.
  Резкая солнечная тень или мокрое пятно воды могут дать ложное срабатывание;
  матовое масло без бликов — пропуск.
* **Окисление против тени и масла**: оксидная плёнка обязана быть локальной,
  менее насыщенной и зернистой. Слабое потемнение на пределе порога
  пропускается (2 FN из 20 на holdout). Сильная общая тень может поднять score.
* **Освещение и баланс белого** напрямую влияют на HSV-диапазоны. На реальном
  цехе нужна калибровка: снять «чистый» узел и узел с известным дефектом,
  подобрать пороги и, при необходимости, `sat`/`val`/`glint_scale` в конфиге.
  Это не переобучение — это настройка порогов на 10–20 кадрах.
* **Масштаб и резкость**: ROI приводится к стороне ≤ 384 px; признаки
  нормированы, но при сильном расфокусе мелкая зернистость и блики исчезают —
  recall падает.
* **Маркер**: если кожух есть, но маркер закрыт, стёрт, засвечен или меньше
  12 px — будет `present=False`. Для правила `guard_removed` это означает
  «нужен повторный кадр», а не сразу «кожух снят». Маркерная проверка не
  защищает от подмены: наклеить такую же метку на другой кожух технически можно.
* **Почему это допустимо для предварительного осмотра**: ложное срабатывание
  ведёт к «осмотреть узел», а не к остановке оборудования; пропуск дефекта
  компенсируется другими каналами (давление, вибрация, ток). Все решения
  объяснимы числами в `evidence`, поэтому инспектор может проверить и
  переопределить вывод.

## 16. Что говорить жюри

* **Объяснимые признаки, а не чёрный ящик.** Каждый балл — это взвешенная сумма
  понятных величин: доля пикселей нужного цвета, отношение градиентов,
  elongation пятна, доля бликов, зернистость. Их видно в `evidence` и можно
  нарисовать на слайде.
* **Нет обучения.** Не нужен датасет реальных дефектов, размеченный дефектологом;
  нет весов модели, нет вероятностного выхода. Пороги лежат в JSON и
  настраиваются на объекте за 10–20 кадров.
* **Работает офлайн и на CPU, детерминированно.** ~9 мс на ROI для трёх
  детекторов (OpenCV 5, ноутбук), ~8 мс на кадр 1280×720 для ArUco. Один и тот
  же кадр всегда даёт один и тот же ответ — важно для разбора инцидентов.
* **Цифры, а не обещания.** На синтетическом holdout (другой seed, пороги
  зафиксированы): ржавчина precision 1.00 / recall 0.975, масло 0.944 / 0.944,
  окисление 1.00 / 0.900; FPR на чистых негативах 0 %. Провалы перечислены
  поимённо — мы их не скрываем.
* **Маркерная проверка — это промышленная практика.** Кожух считается
  установленным, только если его метка видна в его зоне. Это дешевле и надёжнее,
  чем «дообучать детектор кожуха» на двух днях до защиты.
* **Честная граница:** визуальный канал — подтверждающий. Он говорит «есть
  признаки коррозии/масла/окисления, вот числа», а итоговый диагноз ставит
  правило вместе с давлением, вибрацией и электрикой. Ложные срабатывания
  ограничены и объяснимы, а не «нейросеть так решила».
