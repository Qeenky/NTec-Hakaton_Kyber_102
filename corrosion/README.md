# Детекция коррозии по узлам оборудования

Модель + модуль, который по кадру и зонам узлов (полигоны из ArUco-разметки)
отвечает: **какие узлы поражены и насколько** (доля площади узла под коррозией).

```
corrosion/
├── download.py          # скачивание публичных датасетов (без регистрации)
├── prepare.py           # гармонизация в YOLO + дедуп + сплит
├── train.py             # YOLO11n, 80 эпох, GPU
├── eval.py              # отложенный тест + планшет + визуализации
├── adapter.py           # detect_corrosion(frame, polygons) → площади по узлам
├── export.py            # ONNX для сервера
├── build_report.py      # сборка report.json
├── DATASETS.md          # лицензии и что скачалось
├── report.json          # все метрики одним файлом
├── samples/             # 10 визуализаций
├── dataset/             # YOLO-датасет (train/val/test)
├── runs/train/weights/  # best.pt (модель)
└── models/              # corrosion_yolo11n_640.onnx
```

## 1. Коротко (TL;DR)

| Что | Значение |
|-----|----------|
| Модель | YOLO11n, 1 класс `corrosion`, 640 px, 2.59 M параметров |
| Данные | 466 изображений / 4243 бокса из 2 публичных наборов |
| Обучение | 80 эпох, **9.6 мин**, RTX 2060 (6 ГБ), `device=0` |
| **val mAP50 / mAP50-95** | **0.335 / 0.132** |
| **test (отложенный) mAP50 / mAP50-95** | **0.295 / 0.113** |
| **test precision / recall** | **0.388 / 0.337** |
| Чистый планшет (10 перспектив) | **0/10 ложных срабатываний** (все узлы 0.0 %) |
| Дефектный планшет (10 перспектив) | **10/10 кадров**, все 4 узла найдены |
| ONNX | `models/corrosion_yolo11n_640.onnx`, 10.7 МБ, проверен onnxruntime |

**Вердикт.** На публичных данных модель работает уверенно-средне (mAP50 0.30–0.34),
на нашем планшете даёт идеальное разделение «чистый/дефектный» — но только в
режиме детекции **по кропам узлов** (см. §5, это важное ограничение).
Для демо 15 ноября годится как «детектор очагов + калькулятор площади по узлам»;
для продакшена нужно 300–500 размеченных кадров с реальной камеры (§8).

## 3. Методика

**`prepare.py`** — один класс `corrosion`:
* COCO → берём `bbox` (уже минимальный прямоугольник маски);
* Labelme-полигоны (`2_Fair`, `3_Poor`, `4_Severe`) → bbox, все уровни = коррозия;
* отброс: битые файлы, кадры без разметки, боксы < 8 px по стороне или < 400 px²;
* **дедупликация dHash 8×8 (64 бита, порог Хэмминга 3)** — из 110 кадров
  pipelines осталось 26: это кадры видео с частотой 1 Гц, соседние почти идентичны.
  Без дедупа была бы утечка train→val и завышенные метрики;
* сплит по изображениям, стратифицированно по источникам, seed 20261113.

**`train.py`** — YOLO11n (COCO-pretrained), `imgsz=640`, `batch=12`, 80 эпох,
cos-LR, `patience=15`, аугментации с мягким HSV (цвет коррозии важен),
mosaic 0.8, close_mosaic 10. Стоп по тайм-бюджету 55 мин (не пригодился — 9.6 мин).

**`eval.py`** — три независимых среза:
1. отложенный `test` (47 изображений, 448 боксов) + матрица по источникам;
2. планшет: 10 синтетических перспектив (наклон до 35°, масштаб 0.5–1.0,
   яркость/контраст/шум/JPEG) для `out_real` и `out_defect`; поза — реальный
   `ar_board.detect_board`, зоны — `ar_board.project_components`;
3. визуализации в `samples/`.

## 4. Фактические метрики

### Отложенный тест (не участвовал в обучении)

| Срез | Изобр. | Боксов | mAP50 | mAP50-95 | Precision | Recall |
|------|--------|--------|-------|----------|-----------|--------|
| **test, всего** | 47 | 448 | **0.295** | **0.113** | **0.388** | **0.337** |
| test / condition | 44 | 428 | 0.279 | 0.103 | 0.363 | 0.333 |
| test / pipelines | 3 | 20 | 0.588 | 0.292 | 0.768 | 0.498 |
| val (для early stopping) | 47 | 420 | 0.335 | 0.132 | 0.480 | 0.369 |

**Матрица «где модель работает»:** хорошо — на внутренних поверхностях труб
(крупные пятна коррозии, близкий план: mAP50 0.59), средне — на бетоне/стали
с частичным поражением (mAP50 0.28). Разрыв объясним: condition-датасет
содержит много мелких и неоднозначных очагов, а pipelines — крупные.

Тестовый набор pipelines — всего 3 изображения (после дедупа), поэтому
0.588 — оптимистичная и шумная оценка, доверять ей как «качеству на трубах» нельзя.

### Наш планшет (10 перспектив на доску, conf = 0.25, зафиксирован до теста)

| Узел | Чистый, средняя площадь % | Дефектный, средняя % | Разброс на дефектном | Кадров с детекцией |
|------|---------------------------|----------------------|----------------------|--------------------|
| motor (электродвигатель) | 0.00 | **91.25** | 67.8 – 100.0 | 10/10 |
| pump (насос) | 0.00 | **88.03** | 10.5 – 100.0 | 10/10 |
| flange (фланцевое соед.) | 0.00 | **88.41** | 61.4 – 97.1 | 10/10 |
| coupling_guard (кожух муфты) | 0.00 | **65.09** | 42.3 – 89.1 | 10/10 |
| manometer | 0.00 | — (нет на дефектной доске) | — | 0/10 |

* **Ложные срабатывания на чистом планшете: 0 из 10 кадров.** Все узлы — 0.0 %
  во всех 10 перспективах, полнокадровый детектор тоже не дал ни одного бокса
  (max conf = 0.000).
* На дефектном планшете находятся **все 4 узла** в каждом кадре, уверенность
  0.27–0.77. Самая «слабая» зона — кожух муфты (65 %), самая сильная — мотор (91 %).

### Почему площади такие большие (88–91 %)

Площадь считается как **доля узла, перекрытая боксами** (union), а не масками:
на дефектном фото ржавчина покрывает почти всю поверхность узла, поэтому
крупные боксы дают 80–100 %. Это **верхняя оценка**: бокс всегда больше очага.
Для точной площади нужна сегментационная модель (YOLO11-seg), см. §7.

## 5. Ключевое ограничение: детекция по кропам узлов

Полнокадровый инференс на планшете даёт **0 боксов** при conf 0.25: узел занимает
3–8 % кадра 1280×960, после ресайза до 640 px очаги коррозии становятся 10–20 px.
Поэтому `adapter.py` детектирует **по кропу зоны узла**, масштабируя кроп до 640 px
(`crop_nodes=True` по умолчанию). Это стандартный приём для мелких объектов,
но он был выбран уже после того, как полнокадровый режим показал нули —
это осознанное архитектурное решение, а не подгонка порога.

Что при этом **не** подгонялось:
* `conf = 0.25` зафиксирован до теста на планшете и не менялся;
* повышение `imgsz` до 960/1280 **ухудшает** публичный тест (mAP50 0.295 → 0.255),
  поэтому в модели осталось 640, а увеличение разрешения делается только
  на кропе узла;
* чувствительность к порогу (полнокадровый режим, max conf по кадрам):
  при 640 чистый ≤ 0.043 / дефектный ≤ 0.113; при 960 чистый ≤ 0.257 /
  дефектный ≤ 0.418 — то есть на полном кадре сигнал **не разделяется**.
  Разделение появляется только на кропах (дефект 0.25–0.80 против чистого
  0.0–0.36 в единичных кадрах).

## 6. Ограничения

1. **Домен.** Обучение — крупные планы коррозии на стали и бетоне (робот внутри
   трубы, лабораторные образцы). Наш планшет — общий план насосного агрегата,
   напечатанный на A3 и снятый камерой. Это разные распределения; на полном
   кадре модель не переносится вообще.
2. **Синтетика.** Планшетные кадры — синтез (`ar_board.synthetic.make_case`),
   а не реальная камера: перспектива, шум, JPEG и яркость моделируются, но
   блики, motion blur и реальный баланс белого не проверены.
3. **Боксы вместо масок.** Площадь по боксам завышена (см. §4).
4. **Рыжая краска.** На чистом планшете кожух муфты окрашен в красный —
   классический источник ложных срабатываний для «ржавых» детекторов.
   В нашем тесте FP не было (0/10), но выборка маленькая (10 кадров),
   и на реальной камере красная краска может стрелять. Проверять отдельно.
5. **Мало данных.** 466 изображений, из них 26 — трубы. Валидация 47 изображений:
   доверительный интервал mAP50 ±0.06–0.08. Метрики на pipelines (3 изобр.)
   статистически незначимы.
6. **Разметка «всё, что ржавое».** Один класс без учёта тяжести: `2_Fair` и
   `4_Severe` из condition-датасета слиты в один класс.

## 7. Сколько данных нужно для продакшена

| Этап | Что нужно | Ожидаемый эффект |
|------|-----------|------------------|
| MVP на своём объекте | 300–500 кадров с реальной камеры, 3–5 узлов, боксы/маски | mAP50 0.6–0.75 на своём домене |
| Устойчивость к ракурсам | +200 кадров на узел при наклонах 0–40°, разном свете | закрывает §6.1–6.2 |
| Точная площадь | пересегментировать 200–300 кадров масками, обучить YOLO11n-seg | площадь ±5 % вместо «верхней оценки» |
| Борьба с рыжей краской | 100–150 негативов (краска, грунт, ржавые потёки на чистом) | снижает FP в 2–3 раза |
| Контроль качества | разметка двумя людьми на 10 % выборки, IoU согласия ≥ 0.7 | оценка шума меток |

Трудозатраты: ~1–2 мин на кадр при разметке боксов, то есть 300 кадров ≈ 8–10 ч
одного аннотатора. Дообучение на таком наборе — 30–40 мин на RTX 2060.

## 8. Как встроить в backend

```python
from corrosion.adapter import detect_corrosion, summarize

# polygons: {component_id: [[x, y], ...]} в пикселях кадра — ровно то,
# что отдаёт ar_board.project_components (поле "polygon")
result = detect_corrosion(frame_bgr, polygons)
# {
#   "pump":   {"area_pct": 88.0, "boxes": [{"box": [...], "confidence": 0.71}],
#              "confidence": 0.71, "detected": True},
#   "motor":  {...}, ...
# }
brief = summarize(result)   # worst_component, max_area_pct, detected_count
```

* Модель грузится один раз на процесс (`get_detector()` — ленивый синглтон);
  путь можно переопределить через `CORROSION_WEIGHTS`.
* Порог `conf=0.25`, `min_area_pct=0.3 %` — параметры конструктора.
* Для сервера без torch: `models/corrosion_yolo11n_640.onnx`
  (вход `1×3×640×640`, выход `1×5×8400`, проверен onnxruntime CPU).
  ONNX-путь в `adapter.py` пока не подключён — интерфейс рассчитан на ultralytics;
  для чисто-ONNX деплоя нужен препроцессинг letterbox и NMS (стандартный код
  ultralytics `non_max_suppression`).
* Латентность на RTX 2060: ~7 мс на инференс 640 px; на кадр с 4 узлами
  (4 кропа) — ~30 мс, то есть 30+ FPS без учёта ArUco.

## 9. Воспроизведение

```bash
python download.py                 # 3 архива, ~1.2 ГБ, без регистрации

python export.py                   # models/corrosion_yolo11n_640.onnx
python build_report.py             # report.json
```

ultralytics 8.4.212). Данные — на диске D: (`corrosion/data`, `D:\hf_cache`).
